### 2026-08-18 图床缩略图优化（移动端图片展示丝滑化）

- **问题**：移动端图床墙越往后越卡。原图为 1080–1200px 的 webp（118 张 / 27MB），墙却只显示 200px，导致解码位图占满手机内存被反复驱逐重解码、6 并发预下载跑不赢每秒 5 张的放行节奏，出现「停顿 + 连发」的抽风感。
- **方案**：墙展示改用 600px 宽 webp 缩略图，点开放大才加载原图；上传时浏览器自动生成缩略图并随原图一起提交，删除图片时连缩略图一起清理。
- **效果**：缩略图总量 27MB → 4.8MB（约 1/5），解码内存约降到 1/4，预下载窗口轻松跑在节奏前面 → 稳定逐张展示。
- 新增文件：
  - `scripts/gen-picture-thumbs.js`：批量生成 `public/images/pictures/sm/<base>.webp`（600px、q80、增量执行），依赖 `cwebp`；新增 npm 脚本 `pnpm gen:thumbs`。
  - `src/app/pictures/components/picture-thumb.ts`：`thumbUrl()`（原图 URL → 缩略图展示 URL）与 `thumbRepoPath()`（原图 URL → 缩略图仓库路径，供删除用）。
- 改动文件：
  - `src/app/pictures/components/random-layout.tsx`（移动端散落墙）：墙 `<img>` 改用缩略图，缩略图缺失 `onError` 回退原图；放大时切回原图保证清晰；`GallerySequencer` 由模块单例改为 `RandomLayout` 内 `useRef` 实例，修掉多次进出页面 items 数组无限增长的泄漏。
  - `src/app/pictures/components/string-wall.tsx`（桌面端串线墙）：墙 `PhotoCell` 同样用缩略图；放大 `PhotoZoom` 维持走原图。
  - `src/lib/file-utils.ts`：新增 `makeThumbFile()`，用 `<canvas>` 把图片缩成 600px webp `File`（复用 image-toolbox 逻辑）。
  - `src/app/projects/components/image-upload-dialog.tsx`：`ImageItem` file 变体加 `thumbFile?: File`。
  - `src/app/pictures/components/upload-dialog.tsx`：选图后台生成缩略图塞进 `thumbFile`，不阻塞预览，失败留空回退原图。
  - `src/app/pictures/services/push-pictures.ts`：上传时把 `thumbFile` 提交进 `public/images/pictures/sm/<hash>.webp`；删除本地图床原图时连缩略图一并删（由 `thumbRepoPath()` 推出，一一对应）。
- **自洽性**：上传 / 删除 / 展示三处的缩略图路径完全一致（`sm/<hash>.webp`，与原图扩展名无关）；外链图不生成、不删、直接用原图；缩略图缺失自动回退原图，不破图。
- **生效方式**：提交改动（含 `sm/` 目录）并重新部署；以后上传 / 删除图片缩略图全自动，无需手动执行 `pnpm gen:thumbs`。

### 1. 站内搜索（`/search` + Cmd/Ctrl+K 全局命令面板）

- **目标**：全站文章即时搜索，弥补当前仅靠分组浏览的缺口。
- **数据源**：`public/blogs/index.json`（标题/标签/摘要/日期）+ 各文章 `index.md` 正文。
- **方案**：
  - 新增构建脚本 `scripts/gen-search-index.js`，构建期扫描全部文章，生成 `public/search-index.json`（slug、标题、标签、摘要、日期、正文纯文本片段），随部署更新；
  - 搜索页 `src/app/search/page.tsx`：客户端过滤 + 评分，复用博客列表卡片样式，结果高亮关键字，支持上下键选择、回车跳转；
  - 全局面板 `src/components/search-palette.tsx`：挂载到布局层，Cmd/Ctrl+K 唤起，输入即搜。
- **注意**：中文检索建议采用子串匹配 + 二元切分，避免引入过重分词依赖；索引文件需控制体积（正文截断）。
- **工作量**：中。

### 2. 标签页（`/tags`）+ 文章列表标签筛选

- **数据源**：`index.json` 的 tags 字段聚合（数据已具备，无需改发布链路）。
- **方案**：新增 `/tags` 路由，标签云 + 按标签聚合文章列表两种视图，显示各标签文章数；`/blog` 列表页支持 `?tag=` 参数筛选，复用现有 URL 分组参数机制。
- **工作量**：小。

### 3. 归档时间轴（`/archive`）

- **数据源**：`index.json` 按日期分组统计。
- **方案**：年/月双维度时间轴，展示每月文章数与列表、累计篇数；分组逻辑与 `/blog` 列表页共用，避免重复实现。
- **工作量**：小。

### 4. 文章页增强（可拆分为多个独立小项）

- **相关文章推荐**：按共享标签数量排序取 Top N，展示于文末。
- **工作量**：小。

### 5. 暗色模式

- **现状**：主题色为运行时 CSS 变量（`theme.css` + `site-content.json`），天然支持多套主题。
- **方案**：预置「深色」主题色组；切换按钮 + localStorage 记忆，可选跟随系统 `prefers-color-scheme`。
- **注意**：背景图与文章内图片在深色下的观感需逐一检查。
- **工作量**：小。

### 6. 访客统计页（`/stats`）

- **数据源**：`index.json` 全量统计。
- **方案**：纯客户端计算并展示——文章总数、总字数、按年/分类分布、月度更新趋势、热门标签、最长/最短文章；图表用轻量自绘或小型库。
- **可选**：将站点统计替换为 Cloudflare Web Analytics（更轻、隐私友好），替代现有 GA 脚本。
- **工作量**：小–中。

### 7. 工具箱扩展（在现有图片工具箱基础上）

- **二维码生成**：客户端生成（如 qrcode 库），无后端。
- **JSON 格式化 / 校验**：纯客户端。
- **颜色转换**：复用 `src/lib/color.ts` 已有工具。
- **正则表达式测试**：输入即测、高亮匹配。
- **方案**：现有工具箱页扩展为多 tab，或拆分为独立路由。
- **工作量**：中（每项为小）。

### 8. PWA 化

- **方案**：补全 `manifest.json`（名称/图标/主题色）；新增 Service Worker 缓存静态资源（public 内容与构建产物）。
- **注意**：缓存策略需与"内容随部署更新"的发布模型匹配——采用版本化缓存 + 更新提示，避免新文章发布后老用户看到旧内容。
- **工作量**：中。

### 9. 首页小改造

- **首页随机文章卡**：从 `index.json` 随机取一篇展示，带"换一篇"按钮。
- **工作量**：小。
