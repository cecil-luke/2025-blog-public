### 2026-08-18 图床缩略图优化（移动端图片展示丝滑化）

- **问题**：移动端图床照片墙越往后越卡。原因是照片墙里每张图都加载的是高清原图（1080–1200px、共约 27MB），但屏幕上实际只显示 200px 大小，手机内存扛不住，导致不断卡顿。
- **方案**：照片墙改为加载小缩略图（600px 宽，总体积仅约 4.8MB，是原来的 1/5），点击放大时才加载原图保证清晰。上传图片时浏览器自动生成缩略图一并提交，删除时也一并清理。
- **效果**：图片加载速度大幅提升，滑动流畅不卡顿，内存占用降到原来的 1/4。
- 涉及文件：`scripts/gen-picture-thumbs.js`（批量生成缩略图）、`src/app/pictures/components/` 下散落墙与串线墙组件、`src/lib/file-utils.ts`（缩略图生成）、上传/删除服务。
- **生效方式**：重新部署即可；以后上传/删除图片缩略图全自动处理。

- **搜索页**（`/search`）：独立的搜索结果页面，展示完整列表，URL 中的搜索词刷新后不会丢失。

- **生效方式**：构建时自动生成搜索索引，部署后即可使用。索引在用户首次打开搜索时才加载，不影响页面打开速度。

- **方案**：复用已有的 `hideEditButton` 开关范式——新增 `hideConfigButton` 配置项，在网站设置弹窗里提供复选框自行开关，默认不隐藏。藏掉按钮后快捷键仍可打开弹窗，弹窗内的复选框永远可见，不会自我锁死；万一快捷键也失效，GitHub 才是真正的 CMS，可直接改 `src/config/site-content.json` 提交恢复。
- **快捷键统一**：首页原本同时绑了 `Ctrl/Cmd+L` 和 `Ctrl/Cmd+,` 两个键，现去掉 `L`（与浏览器「聚焦地址栏」冲突），全站只保留 `Ctrl/Cmd+,`——语义统一为「进入当前页面的编辑/管理态」：首页开设置弹窗、`/blog` 进批量编辑、`/share`/`/about` 等进各自编辑模式。

### 2026-09-11 Live2D 看板娘

- **功能**：新增自托管 Live2D 看板娘，在首页及 `/blog`、`/projects`、`/about`、`/share`、`/bloggers` 页面左侧固定展示；桌面端可用，移动端自动隐藏。
- **交互**：支持手动切换模型与休息状态，默认每两分钟自动切换一次；刷新后按 `Rem → Kar98k → HK416` 的倒序循环。
- **位置与缩放**：看板娘固定在左侧空白区域，不随页面滚动；浏览器页面放大或缩小时，WebGL 画布会按新的像素比重新适配，避免模型发虚。
- **兼容处理**：运行时过滤不可用的 Cubism 4 `model3.json`，避免第三方组件内核异常导致看板娘卡死。
- **生产修复**：生产构建前显式加载官方 Cubism Core，修复自动部署后 `Live2DCubismCore is not defined` 导致看板娘不显示的问题。
- **本地专用包**：将 `l2d` / `l2d-widget` 的 Cubism 2 源码集成到当前仓库的 `packages/l2d-cubism2`，移除 Cubism 4/6、`Live2DCubismCore` 和 `.model3.json` 依赖；开发与生产构建均直接分析、编译该源码，不再依赖第三方 Core CDN。
- **资源清理**：模型全部改为站内自托管，仅保留 Rem、Kar98k、HK416 三个模型；删除不再使用的 9 个模型、残留目录及未引用的预览图、贴图和语音文件。
- **加载优化**：Rem 纹理从 2048 降至 1024，全部纹理转为 WebP；模型资源由约 72 MB 降至约 5 MB。模型首屏改为页面空闲后初始化，当前模型加载后预加载下一个模型，页面切到后台时暂停 WebGL 渲染。
- **缓存优化**：为 `/live2d/models/*` 增加 7 天浏览器/边缘缓存与 `stale-while-revalidate`，降低重复访问时的模型下载耗时。
- **类型修复**：修正首页卡片布局偏移类型，使 `offsetX`、`offsetY` 支持默认的 `null` 值。
- 涉及文件：`packages/l2d-cubism2/`、`src/components/live2d-widget.tsx`、`src/config/site-content.json`、`src/layout/index.tsx`、`src/app/(home)/stores/config-store.ts`、`public/live2d/models/`、`public/_headers`。

### 1. 归档时间轴（`/archive`）

- **数据源**：`index.json` 按日期分组统计。
- **方案**：年/月双维度时间轴，展示每月文章数与列表、累计篇数；分组逻辑与 `/blog` 列表页共用，避免重复实现。
- **工作量**：小。

### 2. 文章页增强（可拆分为多个独立小项）

- **相关文章推荐**：按共享标签数量排序取 Top N，展示于文末。
- **工作量**：小。

### 3. 访客统计页（`/stats`）

- **数据源**：`index.json` 全量统计。
- **方案**：纯客户端计算并展示——文章总数、总字数、按年/分类分布、月度更新趋势、热门标签、最长/最短文章；图表用轻量自绘或小型库。
- **可选**：将站点统计替换为 Cloudflare Web Analytics（更轻、隐私友好），替代现有 GA 脚本。
- **工作量**：小–中。

### 4. 工具箱扩展（在现有图片工具箱基础上）

- **二维码生成**：客户端生成（如 qrcode 库），无后端。
- **JSON 格式化 / 校验**：纯客户端。
- **颜色转换**：复用 `src/lib/color.ts` 已有工具。
- **正则表达式测试**：输入即测、高亮匹配。
- **方案**：现有工具箱页扩展为多 tab，或拆分为独立路由。
- **工作量**：中（每项为小）。

### 5. PWA 化

- **方案**：补全 `manifest.json`（名称/图标/主题色）；新增 Service Worker 缓存静态资源（public 内容与构建产物）。
- **注意**：缓存策略需与"内容随部署更新"的发布模型匹配——采用版本化缓存 + 更新提示，避免新文章发布后老用户看到旧内容。
- **工作量**：中。

### 6. 首页小改造

- **首页随机文章卡**：从 `index.json` 随机取一篇展示，带"换一篇"按钮。
- **工作量**：小。
